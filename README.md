# portfolio-mcp

The agent-native layer of [saagarpatel.dev](https://saagarpatel.dev): a Model
Context Protocol server that lets any AI agent query Saagar's writing and projects
directly, instead of scraping HTML.

Read-only. Stateless. Public. No auth, no tracking, no database, no runtime egress.

## How it fits

The website stays a pure static site. This server is a **sibling**, not a backend
bolted onto it:

- **Layer 0** (in the `portfolio-index` repo): the build emits a static machine
  corpus — `corpus-index.json`, per-document `corpus/<id>.json`, and
  `.well-known/mcp.json` — served alongside the HTML. Already public.
- **Layer 1** (this repo): a stateless Cloudflare Worker at `mcp.saagarpatel.dev`
  that bakes the Layer 0 corpus into its bundle and serves it over MCP
  (streamable HTTP). Zero runtime fetches.
- **Layer 2** (later): an `npx`/`uvx` stdio package running the same logic locally.

## Tool surface

All read-only. No tool takes a URL or filesystem path (no SSRF / exfil surface).

| Tool | Purpose |
|---|---|
| `search` | BM25 over the whole corpus; optional `section` filter, `limit` |
| `get_document` | Full Markdown of one document by `id` |
| `list_corpus` | The table of contents; optional `type` filter |
| `get_profile` | The "who is this" card (about / now / uses) |
| `list_projects` | Curated public-safe projects + anonymized aggregates |

Documents are also exposed as Resources (`portfolio://essays/{slug}`, `book/{n}`,
`notes/{slug}`, `profile`) for clients that read them.

## Retrieval

BM25 over a baked index (no embeddings in v1 — the corpus is ~48 small docs and
the calling LLM supplies the semantics). Titles are boosted. Embeddings are a
measured Phase 3 upgrade, added only if retrieval quality proves insufficient.

## Layout

```
src/
  types.ts            corpus + projects shapes
  bm25.ts             dependency-free BM25 + snippet (pure)
  tools.ts            createTools(corpus) -> the 5 tools (pure, injectable)
  corpus.ts           loads the baked corpus + accessors
  corpus.generated.ts AUTO-GENERATED by build:corpus (placeholder committed)
  index.ts            MCP server + Worker transport  [pending: see Status]
scripts/build-corpus.mjs  bakes Layer 0 into corpus.generated.ts
test/                 vitest unit tests for bm25 + tools
```

## Develop

```sh
npm install
npm run build:corpus          # bake from ../portfolio-index (or --url=https://saagarpatel.dev)
npm run typecheck
npm test
npm run dev                   # wrangler dev -> http://localhost:8787/mcp
```

Test the live endpoint with the MCP inspector:

```sh
npx @modelcontextprotocol/inspector http://localhost:8787/mcp
```

## Deploy

```sh
npm run build:corpus && npm run deploy   # wrangler deploy -> mcp.saagarpatel.dev
```

Deploy is operator-gated (needs Cloudflare auth). Custom domain `mcp.saagarpatel.dev`
is bound as a Worker route. After deploy, flip `.well-known/mcp.json` `status` from
`planned` to `live` in the portfolio-index repo.

## Audit posture

This server is designed to score Grade A on `mcp-trust` and pass `MCPAudit`
(Saagar's own tools): only the inbound MCP transport, no `shell_execution`, no
`file_access`, no `destructive`, no `exfiltration`, and no caller-controlled
network egress (the corpus is baked, not fetched). Tool descriptions are plain
and non-injectable; every tool is annotated read-only.
